## Context

`WorksListView` 当前分别保存 `selectedMode`、`activeSearchText`、`WorksFilter`、`ReviewFilter` 和播放列表选择。加载作品时，非空的 `activeSearchText` 优先于 `selectedMode`，因此标签、声优、社团或手动搜索都会使用全局 `searchWorks` 与 `WorksFilter`。筛选 Sheet 却只依据 `selectedMode` 选择界面和应用回调，导致从收藏或播放列表发起搜索后出现上下文错位。

搜索期间保留 `selectedMode` 本身是有价值的：它表示搜索前的栏目，清空搜索后可以自然返回该栏目。问题不在于状态被保留，而在于筛选界面把“返回栏目”错误地当成了“当前内容上下文”。

## Goals / Non-Goals

**Goals:**

- 让作品请求、筛选界面和筛选应用行为使用一致的当前内容上下文。
- 搜索激活时始终使用通用作品筛选，不受搜索前收藏或播放列表模式影响。
- 清空搜索后恢复搜索前栏目及其各自保存的筛选状态。
- 用可独立验证的纯状态规则覆盖收藏和播放列表这两个已知错位入口。

**Non-Goals:**

- 不增加“仅搜索收藏”或“仅搜索当前播放列表”的能力。
- 不修改服务端搜索、收藏或播放列表 API。
- 不重置或合并 `WorksFilter`、`ReviewFilter` 与播放列表选择。
- 不重构整个作品列表为新的导航或查询状态机。

## Decisions

### 1. 显式建模筛选上下文

引入轻量的筛选上下文类型，至少包含通用作品、收藏和播放列表三种上下文。由“是否存在已执行的搜索”和 `selectedMode` 共同派生当前筛选上下文：

```text
存在 activeSearchText  ───────────────▶ 通用作品
不存在 activeSearchText + 收藏模式 ──▶ 收藏
不存在 activeSearchText + 播放列表 ──▶ 播放列表
其他栏目 ─────────────────────────────▶ 通用作品
```

筛选 Sheet 接收该上下文，而不是直接接收 `WorksMode`。通用作品上下文展示并应用 `WorksFilter`，收藏上下文展示并应用 `ReviewFilter`，播放列表上下文展示并应用播放列表选择。

选择这一方案是因为筛选界面真正关心的是可用筛选能力，而不是首页栏目名称。它避免通过传入 `.latest` 来间接触发通用界面的语义混淆，也避免后续新增栏目时继续堆叠特殊判断。

### 2. 搜索优先，但保留原栏目状态

搜索激活期间不修改 `selectedMode`，也不重置 `reviewFilter` 或 `selectedPlaylistID`。`activeSearchText` 继续表示已经提交并正在展示的搜索，而不是输入框中尚未提交的文本。

因此，用户仅编辑搜索框但尚未提交时不会提前切换筛选上下文；搜索提交或详情元数据搜索生效后才切换为通用作品筛选。清空搜索后，派生上下文会自动恢复到原栏目。

没有选择“搜索时把模式改为最新”，因为这会丢失用户的返回位置；也没有选择“搜索时禁用筛选”，因为搜索 API 已支持通用字幕和排序条件。

### 3. 保持各类筛选状态彼此独立

搜索使用现有 `WorksFilter`，收藏继续使用 `ReviewFilter`，播放列表继续保存当前列表选择。上下文切换只决定当前展示和应用哪一种状态，不在切换时复制、转换或清空状态。

这能确保搜索中调整通用筛选后，搜索请求立即读取同一个 `WorksFilter`；返回收藏后，之前选择的“想听”“在听”等收藏条件仍然存在。

### 4. 将上下文选择规则做成可测试的纯逻辑

把筛选上下文派生规则放在不依赖 SwiftUI 生命周期的纯函数或类型属性中，并沿用项目现有 DEBUG self-check 方式覆盖关键组合。至少验证：搜索覆盖收藏、搜索覆盖播放列表、无搜索时保留收藏和播放列表上下文、其他栏目使用通用作品上下文。

## Risks / Trade-offs

- [风险] `selectedMode` 名称仍容易被误解为当前数据源 → 通过显式的筛选上下文类型和集中派生规则区分“返回栏目”与“当前筛选能力”。
- [风险] 仅修正 Sheet，未来其他组件仍可能直接依据 `selectedMode` 判断当前内容 → 在实现和验证中检查搜索摘要、请求分支和筛选入口，确保当前行为一致；后续复杂度增长时再考虑统一的作品查询状态机。
- [权衡] 保留多个独立筛选状态会让状态数量不变 → 换取栏目间切换和清空搜索后的状态连续性，且无需无意义的筛选模型转换。
- [风险] SwiftUI Sheet 展示时上下文取值不正确 → 在打开 Sheet 前由当前 `activeSearchText` 派生上下文，并验证收藏、播放列表进入详情搜索后的实际界面。

## Migration Plan

本变更仅调整客户端内存状态的派生和界面分支，无数据迁移或分阶段发布要求。实现后执行现有自检和 iOS 构建，并按关键交互路径验证；如需回滚，可直接恢复筛选 Sheet 使用原 `selectedMode` 的逻辑，不涉及用户数据。

## Open Questions

无。当前产品语义维持全局搜索；收藏内搜索或播放列表内搜索应作为独立能力另行设计。
