# 本地下载设计

## Context

现有 TrackNode 含远端文件 URL，播放器共用音视频队列、字幕和进度恢复。作品详情目前每次启动需在线获取信息。参见 proposal.md。

## Goals / Non-Goals

目标：批量选择、后台下载、持久化状态、可离线访问的作品目录与资源，适配不同设备宽度。
非目标：自建下载协议、云同步、自动清理用户下载、离线在线 TTS 合成。

## Decisions

- 使用 URLSession background downloadTask 和系统暂停/继续能力。后台回调先搬移临时文件，再切到 MainActor 更新状态；AppDelegate 转交后台事件完成回调。
- 单一 DownloadStore 负责 JSON 原子索引与 Application Support/Downloads 文件，排除备份。随机 UUID 文件名加安全扩展名，避免远端路径逃逸。作品 ID 与远端文件身份共同去重。
- 持久化作品与完整目录。详情先显示本地快照，联网更新失败保留目录；播放和字幕统一在共享播放器解析本地 URL，避免修改每个调用方。
- 多选保留跨目录选择，文件夹勾选递归叶子文件；行的文件夹入口仍可进入。全选当前文件夹递归选择；显示选中数和预计大小。重复提交跳过已有下载，失败可重试。
- 下载管理在首页和详情工具栏可达，按作品展示任务状态、进度、存储大小与可点击作品入口。删除需确认，支持全部清理；已下载文件持续保存直到用户删除。
- 音视频批量下载自动附带同目录匹配字幕，以复用字幕与旁白流程。失败和磁盘空间不足展示可重试错误。

## Risks / Trade-offs

- 系统调度及用户强制退出影响后台执行 → 重启连接原 session 并核对系统任务和文件，丢失任务转为可重试失败。
- 下载链接返回 HTML 或不完整内容 → 检查 HTTP 状态、内容类型与已知大小，成功后才标记缓存。
- 普通暂停保留系统任务而非自建分块续传 → 接受系统续传行为，丢失任务可重试。
- 本地空间不足或索引无法保存 → 显示错误；不得将未保存文件标记成功。
- 本地下载含用户内容 → 文件名不含凭据，不参与备份，不写远端日志。

## Migration Plan

无历史下载数据迁移；提升版本为 1.3.0，验证后推送 main 和 v1.3.0，由现有 GitHub Actions 构建发布。
